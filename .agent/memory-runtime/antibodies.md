# 跨项目抗体清单

> 从历史项目中积累的通用踩坑经验，跟随 skill 旅行到新项目。
> POST-3 同步时，仅写入标记为 [跨项目] 的避雷条目。

## 通用抗体

- [AB-001] [并发编辑] 工具写入后若文件内容或时间戳再次变化，必须重读并合并会话外修改，禁止以旧上下文覆盖。（太空飞机弹珠/v0.2.0）
- [AB-002] [游戏分层] 权威玩法随机流与渲染随机流必须隔离，否则不同帧率或后端会改变玩法随机结果。（太空飞机弹珠/v0.2.0）
- [AB-003] [运行验证] 验证器的 engine shader cache 报错不能等同 Lua 失败；应分别核对 lua_errors、resource_errors，并以真实渲染截图交叉验证。（太空飞机弹珠/v0.2.0）
- [AB-004] [跨项目][3D渲染] 基础模型节点的游戏坐标到米制世界坐标必须统一应用缩放因子；创建与每帧更新的 scale 公式必须一致。（太空飞机弹珠/v0.3.0）
- [AB-005] [跨项目][3D性能] 体素场景禁止每体素创建 Node/StaticModel；应按敌人或区块合并为 CustomGeometry，并仅在拓扑变化时重建。（太空飞机弹珠/v0.3.1）
- [AB-006] [跨项目][资源加载] 生成资产的 prefab/material 可能包含未同步 UUID 纹理；交付前必须用本地项目相对路径替换并检查运行时资源错误。（太空飞机弹珠/v0.3.1）
- [AB-007] [跨项目][顶点色] `CustomGeometry:DefineColor` 只有在 Technique 消费 VCol 时才会显示；使用 `DiffVCol` 时绑定白色基底纹理可避免顶点色被缺省采样结果乘黑。（太空飞机弹珠/v0.4.0）
- [AB-008] [跨项目][渲染验证] 后处理 shader cache 编译失败可能吞掉整个 3D pass；若 HUD 可见而 3D 全黑，先逐项关闭 FXAA/Bloom/Vignette，再用无后处理截图验证基础场景。（太空飞机弹珠/v0.4.0）
- [AB-009] [跨项目][动态背景] 大量星点/环境装饰应按层合并为少量 `CustomGeometry` 批次，并置于游戏物体后方，禁止每元素一个 Node 或 UI 层覆盖游戏物体。（太空飞机弹珠/v0.4.0）
- [AB-010] [跨项目][正交斜视] XY 玩法平面从法线方向向正视倾斜角 `a` 时，保持正交投影并用 `(0, d*sin(a), -d*cos(a))` 放置相机；镜头倾斜不能改变玩法平面或车辆绕 Z 轴的朝向语义。（太空飞机弹珠/v0.5.0）
- [AB-011] [跨项目][程序化载具] 高品质程序化车辆应在单个 `CustomGeometry` 中按车漆/轮胎/金属/玻璃/灯光拆固定 section，使用倒角棱台与低段数圆柱，而不是方块瓦片或每部件一个节点。（太空飞机弹珠/v0.5.0）
- [AB-012] [跨项目][瞄准朝向] 待发射载具速度为零，不能沿用飞行速度朝向；瞄准期间必须直接使用“发射点 - 拖拽点”的发射向量计算车头角度，松手后再切回速度朝向。（太空飞机弹珠/v0.6.0）
- [AB-013] [跨项目][3D表现事件] 规则碰撞事件不应由渲染后端直接推导特效；先在 Presentation 维护短生命周期脉冲/冲击波，再让 Scene 与 HUD 同时只读消费，才能保持规则层纯净并统一空间反馈。（太空飞机弹珠/v0.6.0）
- [AB-014] [跨项目][载具转向] 载具朝向必须区分目标角与显示角，并用归一化到 `[-180°, 180°)` 的角差沿最短路径限速追踪；直接赋目标角会造成瞄准与反弹时的瞬切，普通角差还会在跨 ±180° 时绕远路。（太空飞机弹珠/v0.6.1）
- [AB-015] [跨项目][视觉碰撞比例] 程序化载具缩放必须由权威碰撞半径、世界缩放和模型局部平面包围半径共同推导，并保留少量内缩余量；禁止按类型或主/分裂状态叠加脱离碰撞体的经验倍率。（太空飞机弹珠/v0.6.1）

- [AB-016] [跨项目][体素立体表现] 想增强体素厚度时，正面不能只靠光照猜测；应显式为外露背面/侧面/顶面设置浅色顶点色，并把深色棱线作为同一 `CustomGeometry` 的合并 section，避免逐棱节点和内部线条泄漏。（太空飞机弹珠/v0.7.0）
- [AB-017] [跨项目][像素 UI] 像素风 HUD 需要硬边矩形、2px 内描边、零模糊硬阴影、深色表面和高饱和状态色；不要使用圆角面板或将状态信息堆成无层级的文字。（太空飞机弹珠/v0.7.0）
- [AB-018] [跨项目][固定比例画布] 当 3D 游戏叠加 raw NanoVG 且要求固定纵横比时，UI、3D `Viewport` 与输入必须共享同一个 DPR-aware CONTAIN scale/offset：NanoVG 用设计空间变换，Viewport 用对应物理像素 `IntRect`，输入用同一变换求逆；只适配 UI 会导致 3D 铺满或点击错位，非目标比例屏幕应 letterbox 而非拉伸或裁切。（太空飞机弹珠/v0.8.0）
- [AB-019] [跨项目][倾斜正交输入] 固定设计画布坐标不等于倾斜正交相机下玩法平面的屏幕投影；必须用 `Camera:WorldToScreenPoint()` 标定玩法平面的投影 offset/scale（或用屏幕射线与玩法平面相交），输入逆变换、瞄准轨迹和空间反馈共享同一组参数，否则操作点、3D 模型与 NanoVG 轨迹会系统性错位。（太空飞机弹珠/v0.8.1）
- [AB-020] [跨项目][程序化模型中心] 程序化模型即使 XY 原点正确，局部深度方向几何中心偏离零点也会在倾斜相机下产生屏幕位置偏移；节点定位时应按缩放后的局部 Z 视觉中心反向补偿，并与权威平面坐标分开处理。（太空飞机弹珠/v0.8.1）

- [AB-021] [跨项目][主题敌机与隐藏血量] 敌方主题飞机可将砖块阵列重建为单 `CustomGeometry` 的机身/主翼/尾翼/驾驶舱/推进器，但 HP 只留在权威规则层；前期敌人应保持 1 HP，渲染签名不得读取或展示剩余 HP。（太空飞机弹珠/v0.8.2）
- [AB-022] [跨项目][UI安全层] 3D 世界叠加 HUD、底部操作 Dock 和 modal 时，不能仅靠绘制顺序掩盖冲突；应为 HUD/Dock/modal 建立不透明互斥区域，并按游戏状态决定是否绘制轨迹、冲击反馈和弹药槽。菜单主视觉与 CTA 也必须先做几何边界检查，禁止无意相交。（太空飞机弹珠/v0.8.3）
- [AB-023] [跨项目][投影遮挡审查] 倾斜正交相机下，权威玩法坐标不能直接当作屏幕设计坐标判断 UI 遮挡；必须先通过 `WorldToScreenPoint` 标定值或等价投影把对象边界映射到屏幕空间，再决定是否改 UI 或权威规则，否则会误移动危险线、弹弓和碰撞边界。（太空飞机弹珠/v0.8.3）

- [AB-024] [跨项目][体素采样一致性] 当低像素图采样同时驱动规则碰撞与 3D 体素时，occupied cells 必须成为规则、2D、3D 和碎片颜色的唯一共同数据源；体素中心使用权威网格 pitch，视觉 gap 只能缩小单块本体，不能缩短中心间距，否则显示会与逐块碰撞漂移。完整多边形模型也不能覆盖 `alive=false` 的缺口。（太空飞机弹珠/v0.8.4）
- [AB-025] [跨项目][二维体素挤出] 二维 occupied-cell 图挤出为薄 3D 体素时，二维邻居表只能剔除 XY 内部侧面；前后 Z 端面不能查询同一个 `col:row` key，否则当前格会被误判为自己的 Z 邻居，整片正反面消失成线框。（太空飞机弹珠/v0.8.5）
- [AB-026] [跨项目][动态相机投影同步] 使用缓存 `WorldToScreenPoint` 标定连接 3D、NanoVG 和输入时，任何相机位移（含震屏）都会使缓存失效；应在相机变换后无日志刷新当前投影，且瞄准轨迹首点必须锚定权威发射主体中心，避免 3D 模型、Overlay 和输入在同帧使用不同相机状态。（太空飞机弹珠/v0.8.5）
- [AB-027] [跨项目][幸存者化分层] 把游戏改造成肉鸽幸存者循环（持续压力、经验/升级、三选一强化、收紧波次）时，逐块越线扣血、XP 累计、升级触发、波次节奏等规则必须只留在权威 `Game` 层；升级效果只改 `BALL_TUNING` 等规则变量并通过 `GetSnapshot().upgradeChoices` 暴露给 UI，暂停/升级 modal 状态由 `Game.Pause/Resume/IsLevelUp/PickUpgrade` 控制，禁止在渲染或输入层硬编码成长数值、扣血倍率或暂停流程。（太空飞机弹珠/v0.9.0）

- [AB-028] [跨项目][撞飞状态] 被命中的可破坏方块若需要保留飞散表现，必须把“规则碰撞状态”和“视觉飞散生命周期”分离：规则层立即标记不可碰撞并发布事件，表现层维护速度/角速度/生命周期，渲染层只消费表现快照，避免已脱离对象再次参与碰撞或直接消失。（太空飞机弹珠/v0.10.0）
- [AB-029] [跨项目][空间布局] 多个可碰撞编队不能只按中心 X 去重；生成时必须对完整二维 AABB 加间距做候选检查，并提供不会接受重叠位置的确定性 fallback。（太空飞机弹珠/v0.10.0）
- [AB-030] [跨项目][缺失模型回退] 运行时引用内置/项目模型前必须验证资源实际存在；对于一次性低频飞散箱体，若模型不存在或资源路径不可靠，应直接使用闭合 `CustomGeometry` 生成六面体并复用已验证材质，不能仅凭 `GetResource` 返回对象或 build 成功判断可见。（太空飞机弹珠/v0.10.6）
- [AB-031] [跨项目][初始化致命依赖] 渲染/后端 `Init` 的成功返回值只能由必需资源决定；可选资源缺失必须在使用处降级跳过，禁止纳入初始化成功条件。一旦 `Backend.Init=false` 让入口 `Start()` 提前 return，Update/渲染/输入事件全部不会订阅，真机表现为 UI 全黑 + 完全卡死，且 GLES 沙箱可能因资源齐而无法复现。（太空飞机弹珠/v0.10.7）
- [AB-032] [跨项目][瞬时独立节点预算] 每个需要独立 Node 的瞬时视觉对象（飞散箱体/碎片等）都意味着一个 draw call；必须在表现状态层和渲染层分别设置同屏硬上限，超预算丢弃最旧对象，避免高命中频率真机节点堆积导致帧率归零、UI 不刷新。（太空飞机弹珠/v0.10.7）
- [AB-033] [跨项目][规则边界≠屏幕边界] 斜俯视相机下玩法坐标原点不一定在屏幕顶端；反弹墙等规则边界必须按运行时相机投影换算到设计画布，要求“飞出画面才反弹”时就把规则边界和视觉边框一起放到画布投影范围之外，左右边继续对齐，禁止把玩法坐标 0 直接当屏幕顶。（太空飞机弹珠/v0.10.8）
- [AB-034] [跨项目][编队防重叠全域求解] 波次生成的 AABB 检查必须同时覆盖本批次与场上仍存活的单位，并提供“逐层抬高+多 X 槽扫描”的确定性 fallback；逐帧分离要在全部单位位移完成后做多轮全对全求解（边界侧不对称让位、纵向只向屏幕外方向推，避免提前触发越线），再统一钳边界并回写摆动中心，单轮逐机处理会被下一帧摆动/新波次重新拉回重叠。（太空飞机弹珠/v0.10.8）
- [AB-035] [跨项目][%d 浮点中断] Lua 5.4 的 string.format("%d") 遇到浮点直接抛错；UI 快照中凡被倍率/系数作用过的数值字段（经验、伤害等）显示前必须 math.floor，否则单帧 format 错误会中断整段 HUD 绘制。（太空飞机弹珠/v0.10.8）
- [AB-036] [跨项目][顶点色材质] 要让程序化纹理被顶点色染色，材质 Technique 必须消费顶点色（如 DiffVCol）；普通 Diff 不读顶点色会让灰白纹理盖住整机颜色。程序化金属/面板纹理基底灰度应压到约 0.6，避免冲淡主色。（太空飞机弹珠/v0.10.9）
- [AB-037] [跨项目][像素资产槽位化配色] 用像素数据驱动多类单位配色时，像素 RGB 只作“部件槽位”分类（座舱/引擎/主装甲/暗装甲），最终颜色走每类单位统一配色表；分类阈值必须用实际像素值标定（如座舱是高亮蓝 b-r≥55，灰蓝装甲 b-r≈30 不能混为座舱）。（太空飞机弹珠/v0.10.9）
- [AB-038] [跨项目][随机选项去重] 加权抽卡给同一面板选 N 项时，跨次叠加上限和“同面板去重”是两件事：必须用本次抽取的已选集合过滤候选，否则同一张升级面板会出现两个同名选项。（太空飞机弹珠/v0.10.9）
- [AB-039] [跨项目][节奏数值联动] 调“刷怪过快/升级过快”时必须联动四处：BALANCE 间隔与同屏上限、每波数量函数、ResetGame 首波冷却、同屏上限增长分母，以及 XP 首阈值与指数成长；只调一处会留下密度/成长失衡。用时长探针（固定秒数内波次数与等级）验收而非主观判断。（太空飞机弹珠/v0.10.10）
- [AB-040] [跨项目][屏外生成与无突跳进场] 斜俯视相机下“屏幕顶”不等于玩法 y=0，刷怪起始 y 必须按单位自身高度整机放到可见顶投影之上（如 visibleTop - height - margin），随机候选只在该屏外层选 X，禁止随机 y 落入可见区；新单位摆动相位必须初始为 0（首帧位置=基准 X），否则随机相位会造成生成瞬间横向突跳；逐帧防重叠在任一方仍在屏外时只做纵向排开，双方进场后才允许横向让位，重叠判定加 >1px 容差防浮点误推。（太空飞机弹珠/v0.10.11）
- [AB-041] [跨项目][按行结算的越线惩罚] 多个单位/方块在同一帧越过防线时，应先按“行（或自然分组）”归并再结算：每组分块碎裂播放视觉但不计击毁奖励（它是惩罚不是玩家击杀），伤害在整体合计后只扣一次（如 max(1, ceil(组数*每线基础))+全局加成），升级加减伤必须是整体加项而不是逐块乘，避免一帧多块把基地血瞬间打空或奖励/反馈事件刷屏。（太空飞机弹珠/v0.10.12）
- [AB-042] [跨项目][文本自动换行与去资源依赖] UI 长描述不能按固定字数硬切（会截断中文/混排），用 nvgTextBounds 实测宽度并按 UTF-8 字节步进取字符做贪心折行，固定详情区行数并把标签/数值/层数放到独立底部区避免重叠；HUD 的小图标优先 NanoVG 程序化绘制（汉字徽标等），不要为可绘制内容引入外部 PNG 依赖导致缺图空白。（太空飞机弹珠/v0.10.13）
- [AB-043] [跨项目][引擎绑定返回值≠C API] tolua++/生成绑定的函数返回值形态可能与上游 C API 不同，照搬 C 文档的多返回值解构会静默拿到 nil 并永远走 fallback。UrhoX 的 `nvgTextBounds(ctx,x,y,str,nil)` 实际返回 `(advance, boundsTable)`，boundsTable 是 `{minx,miny,maxx,maxy}` 数组；正确写法 `local _,b = nvgTextBounds(...); local w = b[3]-b[1]`。该测量还受当前 transform 影响（CONTAIN scale=2 时返回物理像素宽度），测量须包在 nvgSave/nvgResetTransform/nvgRestore 内；UTF-8 文本 fallback 估宽用 utf8.len（字符数），禁止用 #s（中文字节数×3）。症状是中文每行只容 4-5 字且功能不报错，必须靠截图才能发现。（太空飞机弹珠/v0.10.14）

- [AB-044] [跨项目][相对拖拽输入] 触屏拖拽类操作（弹弓/瞄准/虚拟摇杆）不要限定在主体附近的小热区起手，也不要让被操控物直接跳到手指下（手指会遮挡主体与目标）。正确做法：按下时记录 grabStart，操控量=当前点-按下点并钳制最大幅度，被操控物只在自己的锚点附近按操控量移动；这样屏幕任意位置都能起手且不遮挡。保留各轴独立钳制（如下位移不能把主体拖出安全区）和小幅度死区松手归位。（太空飞机弹珠/v0.10.15）
- [AB-045] [跨项目][不要发明多余机制] 用户反馈"等待空窗/不好用"时，先确认现有自然流程是否已覆盖（如投射物本就会自然回落补弹），禁止自作主张叠加新机制（主动召回、预约发射等）——这类机制往往误触吞输出、与快速操作冲突、连环引出新 bug，最终被整体回滚（太空飞机弹珠 v0.10.15 加召回→v0.10.16 打补丁合流→v0.10.17 全部删除）。应优先做最小修正：缩短自然流程（回收点提前）、修判定 bug、必要时加速自然回落；提出新交互机制前必须先和用户确认。空窗提示类 UI 同理，没有真实可操作行为时不要画"点击召回"按钮。（太空飞机弹珠/v0.10.17）

- [AB-052] [跨项目][透明软粒子的材质选择] Billboard/CustomGeometry 想要"彩色 + 软边/异形（圆、三角、烟雾）+ 半透明"时，逐 technique 探针得到的结论：不透明的 DiffVCol/DiffVColAdd 会**忽略纹理 alpha 通道**（软圆贴图显示成方块）；而 DiffAlpha 虽然**读纹理 alpha 做混合，却不读 billboard 顶点 rgb**（白纹理+彩色顶点不会染色，顶点色只影响 alpha/开关）。因此唯一可行路径是：把颜色**烘焙进程序纹理本身**（Image 逐像素写 rgba，软边用径向渐变、异形用遮罩），材质用 DiffAlpha + 该纹理，顶点色保持白；生命周期淡出/消散靠尺寸收缩或纹理自带 alpha，不要靠顶点 rgb。不透明彩色体素仍用 DiffVCol+顶点色（AB-036），按是否需要透明软边二选一。另：Billboard 贴图 UV 的 V 轴相对 Image 的 y 翻转，画有方向的形状（如尖朝上的三角）时要在图像里反向画。（太空飞机弹珠/v0.10.21）

- [AB-054] [跨项目][斜俯视正交相机的 z 会投影到屏幕] "正交相机下 z 不影响屏幕 XY"只对**纯俯视/正视**成立；相机是斜俯视（如 46° tilt）正交投影时，物体的 z 会投影到屏幕 Y，同 XY、不同 z 的两个点在屏幕上明显错位。因此任何要"贴在"3D 玩法对象上的辅助物（瞄准线起点、指示标记、吸附特效），z 必须取该对象实际锚点的世界 z（整条辅助元素用同一 z 平面），不能图省事放固定的近相机 z——否则规则坐标完全正确（日志里 x1,y1==对象 x,y）但画面上整段线/标记脱离对象，排查时容易误以为是规则层算错。纯全屏、不需吸附对象的覆盖物才可用独立 z。（太空飞机弹珠/v0.10.22）

- [AB-073] [跨项目][Update 晚于体素世界步进] 玩法订 `Update` 时，VoxelPhysicsWorld 本帧已步进完毕。手改 occupancy 后只 `MarkRegionDirty` 会把网格重建推迟到下一帧；物体还活着时看起来就是幽灵块一直不刷新。必须同帧 `RebuildGeometry()`，并用 `SetSolid`/`IsSolid` 确认 occupancy 真被清掉。文档说“世界本帧驱动重建”只适用于改网格发生在 SceneUpdate/步进之前。（击碎，飞机大战/v0.10.37）

- [AB-075] [跨项目][商业化设计先定三色语义] 把游戏 UI 改成带变现入口的版本时，先固定颜色语义再排版：绿色=看广告（免费获取）、金色=付费/稀有、青色=既有品牌强调色（焦点/主操作/进度），红色只留给错误/低血/危险。三色混用会让玩家分不清"哪个要花钱、哪个看广告就行"。另注意引擎侧可能只有激励视频一种广告 API（无横幅/插屏），出方案前先确认可用能力，别按插屏/开屏方案设计。（击碎，飞机大战/v0.11.0-design）
- [AB-076] [跨项目][单机广告变现天花板在触点密度] 单机小游戏只靠激励视频时，收益 ≈ DAU × 人均观看次数 × eCPM。常见的失败形态是"广告位已开通，但全流程只有一个触发点（如死亡复活）且每局限一次"，人均观看被锁死在 1 次左右，与成熟休闲产品差 5–10 倍。补触点前先看有没有软货币和 meta 层：没有软货币，"结算双倍""皮肤解锁""开局强化"都无处落脚；没有 meta 层，DAU 本身就是更大的瓶颈。内购通常要求服务端发货（多人架构），纯单机做不了，不要为内购强改架构。（击碎，飞机大战/v0.11.0-design）
- [AB-077] [跨项目][设计稿落地必须重对齐命中契约] 设计稿（mockup）只是方向候选，不能直接当实现规格：稿子里新增的按钮（重抽/升阶/解锁）很容易压掉原有卡片点击区。落地任一方案前，必须把视觉几何、命中常量、安全层边界（如 HUD 高度、Dock 高度、卡片 168×300@cy530）重新对齐同一套常量，且控制广告弹窗密度（单局 ≤3–5 次，禁止死亡瞬间连弹两个）。（击碎，飞机大战/v0.11.0-design）

- [AB-078] [跨项目][广告变现先立三件套] 单机激励视频要从「一个触点」扩成闭环，必须先立地基再铺触点：①**软货币**（跨局持久化）——没有它，"看广告双倍结算""皮肤解锁""开局强化"全都无处落脚；②**存档层**（本地文件 + 云变量合并，云合并取大值/并集，换设备不回退）；③**统一广告调度层**——在途锁 + 冷却 + 一次性 completed + `embed manual close` 归失败 + 「未受理且无回调时自行收尾」（否则 UI 卡在加载态）。业务代码禁止再写裸 `ShowRewardVideoAd`。触点先做**局内情绪最高的那一个**（如肉鸽三选一的"重抽"），性价比远高于铺一堆入口。（击碎，飞机大战/v0.11.0）
- [AB-079] [跨项目][结算类奖励必须幂等 + 复活后重开] "本局产出 → 结算入库"要写成幂等：用 settled 守卫让「每帧调用」安全。但**带复活机制的游戏必须注意**：复活后本局继续，如果守卫不复位，复活后新赚的产出会被静默吞掉。ReviveFromAd/续关类接口里要把 settled/doubled/已结算数额一起复位。（击碎，飞机大战/v0.11.0）
- [AB-080] [跨项目][变现 UI 的命中几何要收敛到单一来源] 给面板加变现按钮时，最危险的不是文案而是**命中漂移**：main.lua 自持的卡片常量与后端绘制常量会悄悄分叉。做法是把命中判定整个搬进渲染后端（`HitTestXxxPanel` 返回 `kind,index`），视觉几何与命中同源。两个坑：① 角标/小按钮**必须先于**卡片本体判定，否则点角标会被当成选卡；② 想加"第 N 个候选"时先算宽度——3×168+gap 已占满 540 画布，第 4 个必须换形态（画成下方宽卡），不能按 `#choices` 均分宽度。（击碎，飞机大战/v0.11.0）

- [AB-081] [跨项目][三色变现语义要落成颜色令牌再铺 UI] 商业化 UI 一旦开始铺按钮，最容易翻车的是"看广告"和"免费领"长得一样。做法：先在调色板里加**独立的广告色令牌**（绿 `ad/adDim`），与品牌强调色（青＝主操作/进度）、稀有/付费色（金）三分，然后逐个按钮套用——免费领取用青色、看广告一律绿色、稀有度与数值徽标才用金色。落地时拿设计稿逐张对照，别凭印象。反面案例：把广告按钮画成金色，玩家会以为要花钱。（击碎，飞机大战/v0.11.0）
- [AB-082] [跨项目][面板的"命中几何"必须与绘制同源且是纯函数] 给面板加按钮时，把命中判定整个搬进绘制模块并返回 `kind,index`。⚠️ 关键陷阱：命中函数里**不能调用会画图的外壳函数**（`Shell(ctx=nil,...)` 内部会调 backdrop/text，ctx 为 nil 直接崩）。要把「纯几何」与「绘制」拆成两个函数：`GetXxxLayout(w)` 只算矩形、`DrawXxx(ctx,...)` 才画，命中与绘制都调前者。另：模块间共享样式用**依赖注入**（`Init{deps}`）而不是互相 require，否则要么循环依赖、要么样式漂移。（击碎，飞机大战/v0.11.0）
- [AB-083] [跨项目][HUD 满了要按"空白带"找位置，别硬塞] 老游戏的 HUD 通常三行已满（左右中三列各自 2-3 行 + 血条 + 经验条）。加新读数前先把现有元素的坐标列一遍，找到真正的空白带再放，不要凭感觉挑个好记的坐标。反面案例：把「零件 +N」放在 (14,70)，正好压在「等级」上。另有一个环境坑：某些 headless 截图输出的是**未压缩 PNG**，文件大小由分辨率唯一决定（1080×1920 恒为 8,305,983 字节），**不能用文件大小判断截图是否更新**，只能真的读图。（击碎，飞机大战/v0.11.0）

- [AB-084] [跨项目][纯单机想接内购，用"单机间接联机"而不是重做玩法] 内购发货跑在服务端（`Shop.onDeliver`），所以纯单机接不了 IAP。但**不需要把玩法改成联机**：入口 `main.lua` 只做分流（`IsServerMode()` → 服务端模块，否则 → 客户端玩法），服务端 headless **只承载 IAP 发货 + 权威货币余额**，不复制场景、不模拟玩法。配置用 `player_number:1 + immediately_start`（1 人秒开），大厅 5s 超时即 `SetOffline(true)` 降级本地。这样既有服务端权威的钱，又不动一行战斗逻辑。代价：多一层大厅生命周期，且要处理离线分支。（击碎，飞机大战/v0.12.0）
- [AB-085-FIX] [跨项目][「3D 正常但 2D 界面全没」= 启动期崩溃，别先怀疑渲染层] ⚠️ 这条订正 AB-085 的归因。真机现象：3D 场景可见（星空/边框），但 HUD/菜单/弹窗全无。第一反应会去查 NanoVG 渲染层——**错了**。真实原因往往是 `Start()` 中途抛错（本次 `NetClient.Start` 为 nil），导致**它之后的所有 `SubscribeToEvent` 都没执行**；而 3D 是 `Backend.Init()` 里建好的静态场景，不依赖 Update，所以照常显示。**排查动作：先在日志里 grep `Execute Lua function failed` / `attempt to call a nil value`，再看渲染。** 加固：可选子系统（联机/云/广告）一律 `pcall` 包裹 + 失败降级，禁止让它们有能力中断游戏启动。
- [AB-087] [跨项目][被 require 的模块禁止定义全局 Start/Stop] `function Start()` 写在模块文件里会挂到 `_G.Start`，**覆盖入口脚本的 `Start`**；随后入口里 `Module.Start()` 取的是模块表的字段 → nil → 崩，而且报错位置在模块文件，极具误导性。被 require 的模块一律写 `function Module.Start()`；只有入口文件允许定义全局 `Start`/`Stop`。同理适用于任何可能和入口重名的通用名（Init/Update/Run）。
- [AB-085] [跨项目][SubscribeToEvent 优先传函数引用而不是函数名] 引擎按**函数名字符串**解析事件处理器，所以 `local function HandleXxx` 或闭包内的函数**订阅不上且不报错**（静默失效，最难查）。需要转发时用「模块级引用 + 文件级 `function HandleFileScoped`」两段式。同理，把玩法从一个文件搬到另一个文件时，只要 `function HandleXxx` 仍是全局（没加 local），跨文件订阅依然成立；改 `Start`/`Stop` 这类会和入口重名的函数时才需要收进模块表。（击碎，飞机大战/v0.12.0）
- [AB-086] [跨项目][两套云别混用：自己的存档 vs 给别人发货] 同时有 clientCloud / serverCloud 时按「数据归属」分工，不要按「项目已经联机了」一刀切搬服务端：`clientCloud` 管**自己的**排行榜/成就/养成存档（客户端读写自己那行），`serverCloud` 管**给别人写**的货币发放（任意 userId、事务 + orderId 幂等、离线补发）。把排行榜搬到服务端只在三种情况下值得：要防客户端改分、成就与付费绑定、需要给别人写分。都不满足时搬过去纯粹是给自己加复杂度。氪金代币的**扣款**则必须留在服务端：客户端只发"申请"，服务端 `MoneyCost` 成功后才发本地奖励。（击碎，飞机大战/v0.12.0）
