# 跨项目抗体清单

> 从历史项目中积累的通用踩坑经验，跟随 skill 旅行到新项目。
> POST-3 同步时，仅写入标记为 [跨项目] 的避雷条目。

## 通用抗体

- [AB-001] [并发编辑] 工具写入后若文件内容或时间戳再次变化，必须重读并合并会话外修改，禁止以旧上下文覆盖。（燃烧的蔬菜/v0.2.0）
- [AB-002] [游戏分层] 权威玩法随机流与渲染随机流必须隔离，否则不同帧率或后端会改变玩法随机结果。（燃烧的蔬菜/v0.2.0）
- [AB-003] [运行验证] 验证器的 engine shader cache 报错不能等同 Lua 失败；应分别核对 lua_errors、resource_errors，并以真实渲染截图交叉验证。（燃烧的蔬菜/v0.2.0）
- [AB-004] [跨项目][3D渲染] 基础模型节点的游戏坐标到米制世界坐标必须统一应用缩放因子；创建与每帧更新的 scale 公式必须一致。（燃烧的蔬菜/v0.3.0）
- [AB-005] [跨项目][3D性能] 体素场景禁止每体素创建 Node/StaticModel；应按敌人或区块合并为 CustomGeometry，并仅在拓扑变化时重建。（燃烧的蔬菜/v0.3.1）
- [AB-006] [跨项目][资源加载] 生成资产的 prefab/material 可能包含未同步 UUID 纹理；交付前必须用本地项目相对路径替换并检查运行时资源错误。（燃烧的蔬菜/v0.3.1）
- [AB-007] [跨项目][顶点色] `CustomGeometry:DefineColor` 只有在 Technique 消费 VCol 时才会显示；使用 `DiffVCol` 时绑定白色基底纹理可避免顶点色被缺省采样结果乘黑。（燃烧的蔬菜/v0.4.0）
- [AB-008] [跨项目][渲染验证] 后处理 shader cache 编译失败可能吞掉整个 3D pass；若 HUD 可见而 3D 全黑，先逐项关闭 FXAA/Bloom/Vignette，再用无后处理截图验证基础场景。（燃烧的蔬菜/v0.4.0）
- [AB-009] [跨项目][动态背景] 大量星点/环境装饰应按层合并为少量 `CustomGeometry` 批次，并置于游戏物体后方，禁止每元素一个 Node 或 UI 层覆盖游戏物体。（燃烧的蔬菜/v0.4.0）
- [AB-010] [跨项目][正交斜视] XY 玩法平面从法线方向向正视倾斜角 `a` 时，保持正交投影并用 `(0, d*sin(a), -d*cos(a))` 放置相机；镜头倾斜不能改变玩法平面或车辆绕 Z 轴的朝向语义。（燃烧的蔬菜/v0.5.0）
- [AB-011] [跨项目][程序化载具] 高品质程序化车辆应在单个 `CustomGeometry` 中按车漆/轮胎/金属/玻璃/灯光拆固定 section，使用倒角棱台与低段数圆柱，而不是方块瓦片或每部件一个节点。（燃烧的蔬菜/v0.5.0）
- [AB-012] [跨项目][瞄准朝向] 待发射载具速度为零，不能沿用飞行速度朝向；瞄准期间必须直接使用“发射点 - 拖拽点”的发射向量计算车头角度，松手后再切回速度朝向。（燃烧的蔬菜/v0.6.0）
- [AB-013] [跨项目][3D表现事件] 规则碰撞事件不应由渲染后端直接推导特效；先在 Presentation 维护短生命周期脉冲/冲击波，再让 Scene 与 HUD 同时只读消费，才能保持规则层纯净并统一空间反馈。（燃烧的蔬菜/v0.6.0）
