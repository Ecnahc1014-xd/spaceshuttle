# 跨项目抗体清单

> 从历史项目中积累的通用踩坑经验，跟随 skill 旅行到新项目。
> POST-3 同步时，仅写入标记为 [跨项目] 的避雷条目。

## 通用抗体

- [AB-237] [跨项目][倒置列表滚动符号] 从下向上增长的列表若布局为 `bottom-index*step+offset`，向高条目滚动需要正 offset，合法范围应为 `[0,contentH-viewH]`，不能复制普通列表的负范围。默认定位与拖动必须共用该约束；少内容居中偏移落在布局内，命中同源。测试要断言真实位置变化、双端可见、边界钳制、拖后不误点与轻点仍有效，不能只测「拖过」布尔。（货车大战飞机/stage-scroll-fix，2026-10-09）
- [AB-238] [跨项目][宿主 HTTP 错误证据边界] `XMLHttpRequest response: {}` 的累计错误数不等于请求数；Lua pcall、业务成功日志、未匹配到本地的版本哈希均不能单独证明根因或旧包。应关联同会话 URL/方法/状态/响应类型/initiator 与定义明确的运行版本；UTC/北京时间差 8 小时不能直接排除相关日志。缺 HTTP/宿主通道时保留「尚未定位、尚未验证消除」，不禁云或过滤日志冒充修复。历史资源固定引用链只在 sources/adopt/manifest 与失败资源证据吻合时成立。（货车大战飞机/stage-scroll-fix，2026-10-09）

- [AB-213] [跨项目][击毁反馈要验证事件语义和模态实际绘制] 机体被移除不等于被玩家完整击毁：越线/逃脱/胜利清退不可误触发全毁反馈，领域事件应显式带完整击毁事实和几何尺寸，表现层不从空场反推。实际伤害或清机经验可能在同帧触发升级，Boss 击败可能进入胜利；击毁事实应在最后存活块消失时发布，不能只等可能被升级早退跳过的奖励结算事件。事实与奖励分流，避免选卡后延迟出现或重复播放；事件没有丢并不代表特效已经可见，playing-only 绘制门控加持续衰减会把短反馈吞掉。只为新反馈提供模态空白带的紧凑回声，不放开全部旧 world-fx、不压卡片文字与按钮，也不把回声误作真实伤害范围。回归应包含两条真实升级路径、胜利与清退反例、实际 Draw 返回数/实图、对象池预算与寿命；轻震采用 max 而非多事件相加。（货车大战飞机/v0.13.54，2026-10-08）

- [AB-210] [跨项目][技能冷却要约束真实结算、就绪状态和提示三条链] 给技能加 CD 时只拦伤害会留下「CD 未到却提示可用」：命中消费后旧反弹函数立刻再武装、发 ready 事件，表现层因此承诺无法兑现的能力。应将「待冷却资格」与「实际就绪」分开，CD>0 不发 ready，到期从 pending 自动恢复（不能额外要求一次反弹）。消费事件带实体 id，清该实体旧就绪提示；同帧 ready→hit→consumed 最终无残字，其他实体不误清，对象池复用时重置身份字段。测试必须覆盖真实事件序列与 Presentation 最终状态，而不只断实际伤害间隔；旧测试若接受立即 rearm，不能用旧 PASS 否认用户反馈。（货车大战飞机/v0.13.52，2026-10-08）

- [AB-189] [跨项目][风格身份与效果保全] 用户要求「变贵」不等于授权替换项目风格，要求「找回风格」也不等于授权删除材质厚度、受光、柔光和动态。先读指定规范并核对真实版本diff，在自身语言中增强，保留适配/命中/门控/生命周期与已存在效果；仍有弱暗线在动不代表原效果强度已保留。助手实现与技术验收不是用户审美认可。（击碎，飞机大战/v0.13.39~40，2026-10-08）
- [AB-191] [跨项目][素材规范作用域] 像素资产的母版/限色/二值alpha/NEAREST约束只约束对应资产，不自动禁止NanoVG程序化面板渐变、受光或环境柔光。分开资产合规、表面工艺和读数可读性，不能用规范误扩张为大面积效果删减；同色族工艺先于文字绘制、低频动态共时钟、短控件裁剪按尺寸钳制。（击碎，飞机大战/v0.13.40，2026-10-08）
- [AB-192] [跨项目][实际原图ROI] 视觉A/B像素取证须用原图尺寸与实际CONTAIN scale/offset换算设计ROI，不用工具缩略图尺寸写死坐标。先验证ROI落在目标图元，再判差异；0变化可能是测错区域，不应为过断言修改正确代码。固定种子/时间步/目标相位，排除无关主视觉变化，失败与纠正结果都保留。（击碎，飞机大战/v0.13.40，2026-10-08）
- [AB-190] [跨项目][限色审计口径] 「每图颜色数量合格」不代表符合项目固定色板；同时检查可见RGB集合、透明RGBA总数、alpha二值和母版尺寸。少量漂色优先最小映射并对比逐像素变化、保持轮廓/alpha/文件名/uuid，不重出整套；字标与图标可使用不同的明确色板，不能互相套用。（击碎，飞机大战/v0.13.39，2026-10-07）

- [AB-186] [跨项目][字体测绘一致] 字号自适应与折行必须使用绘制端同字号对应的字体face，不能测regular却画bold。NanoVG测量应在有效绘制帧内、重置transform后验证；本项目Update回调中的测字误报19位余额能装下，实际绘制阶段才能可靠复现与断言。（击碎，飞机大战/v0.13.38，2026-10-07）
- [AB-187] [跨项目][素材分类与环境构图] 先区分像素图标与环境插画，不能把32×32/限色/NEAREST规则套到高清机库背景。环境按原始纵横比cover并裁剪，不拉伸；商品与背景分层，真实模型仍独立渲染，首页避免双环境叠出亮条。可选图片缺失局部降级，释放图片句柄早于宿主context删除。（击碎，飞机大战/v0.13.38，2026-10-07）
- [AB-188] [跨项目][最低字号饱和] FitText必须测量minimum档并返回是否装得下，不能只停在最低字号假定成功。饱和时给数值扩容或分行，保留全部数位，不用无限缩字或省略号吞数字；按实际列宽及真实绘制阶段检查最坏样本，而非仅在Update里打印PASS。（击碎，飞机大战/v0.13.38，2026-10-07）

- [AB-182] [跨项目][UI混合渲染] 在已有NanoVGRender帧内嵌入UI控件，使用官方RenderWidgetSubtree与同设计坐标absoluteLayout，不再UI.Render/BeginFrame；只销毁自有子树，不能UI.Shutdown误删宿主共享context。独立提交探针要让宿主和注入消费者都取同一版本，不能HEAD后端配并发新增依赖的UI模块。（击碎，飞机大战/v0.13.33-battle）
- [AB-183] [跨项目][HUD边界验收] 大数值不能只靠无限缩字，优先拆开标签和数字给足数值宽度；角标既要在设计画布内，也要落在宿主可点击矩形内。样本至少覆盖长数值、字体回退、收起/展开、用过道具和真实进关过渡后的发射；双次Update的展示副本截图不能证明掉血滞后时间正确。（击碎，飞机大战/v0.13.33-battle）

- [AB-179] [跨项目][审美验收] 用户在多轮渐变/柔光/悬停/扫光后仍说「不够贵」，说明这些技术改动未获审美验收；不能拿构建成功、像素数量或新增装饰替代满意度。下一轮先检查游戏身份、商品展示与视觉主次，助手自选方案明确标为待用户验收。（击碎，飞机大战/v0.13.32）

- [AB-181] [跨项目][RT验收] 3D渲染到NanoVG纹理时，分开验证几何世界姿态、Camera投影与最终RT采样；先用上下色标查Y翻转，再看宿主实图，不能只数彩色像素。取景按真实bbox/全动画范围计算，并检查SetOrthoSize后的aspect值；释放目标图像包装必须早于宿主共享context销毁。（击碎，飞机大战/v0.13.32；GLES实测）

- [AB-136] [跨项目][CustomGeometry 空顶点缓冲报错：新建后先禁用节点，清空/收尾不要 Commit 0 顶点] 引擎在节点启用时会绘制其 CustomGeometry，而**刚创建（或刚 Clear()）的几何体顶点缓冲是空的** → 报 `VertexBuffer is empty\!Material ,compute:(nil),vertexBufferSize:1,geomerty type:0`。三处高发：①新建 CustomGeometry 后还没提交几何、节点就已启用（本项目尾迹批次，日志时序可见 `ready` 后 ~76ms 报错）；②清理路径 `Clear()` 之后又 `BeginGeometry+Commit` 提交了 0 顶点；③每帧同步时"本该有内容"的分支因数据为空而提交了空几何。正确做法：**创建后立即 `node.enabled=false`，等提交了非空几何再 `enabled=true`；清空/收尾只 `Clear()`+禁用节点，绝不 Commit 空内容；同步时先判 `#verts>0` 再重建**。⚠️ 这类错误**只在真渲染时出现，LSP 与 build 都发现不了**——新增任何程序化几何（CustomGeometry/动态网格）都要在本地真渲染跑一遍并 `grep VertexBuffer`。（击碎，飞机大战/v0.13.11）

## AB-177（v0.13.30）界面「太便宜/不够贵」→ 先找共用原语，别逐屏重画
- **现象**：用户说「对一个商业化游戏来说现在的大多界面太便宜了」，第一轮改完仍「还是不够贵」。
- **做法**：先 grep 出**所有界面共用的绘制原语**（本项目 `DrawMachinedPanel`/`DrawWindowShell`/`DrawModalBackdrop`/`MetaUI.Button` 覆盖全部 13 个界面），改这几个 = 全屏生效，且签名/命中几何不变、调用点零改动。
- **「贵」的物理来源是层次**：渐变跨度（旧 ±5 RGB 等同纯色 → 新 ~19 级）、**真实柔光**（`nvgRadialGradient` 径向底 + `nvgBoxGradient` 窗口外辉光）、厚度（投影/倒角/受光斜面）、焦点（暗角）。第一轮只加渐变与螺钉不够；第二轮补柔光与环境光后才成立。**先补光/厚度/焦点，再谈装饰线**。

## AB-178（v0.13.31）「华丽/动态」= 交互反馈 + 持续动画，不是静态装饰
- **现象**：质感（渐变/柔光/厚度）做足后，用户仍连说两轮「还不够华丽！还不够交互，还不够动态」——根因是产出全是**静止画面**。
- **做法**：①交互反馈（指针悬停→加色外辉光+亮边，强度用**平滑**值渐亮渐灭）；②持续动画（CTA 周期性扫光、分区标题呼吸+流动光点）。只在**共享原语入口**各加一处，不逐屏做。
- **全屏共享一个动画时钟**：本项目 `uiFx.anim`（`UpdateScene` 写 `gameSnapshot.elapsed`）是唯一相位源，所有呼吸/流动/扫光派生自它 → 元素才同步；各自取 elapsed 会相位不一致。
- **悬停要全局喂入**：`HandleMouseMove/HandleTouchMove` 的 `SetPointer` 必须在所有 return **之前**（否则拖拽/模态时悬停失效）；坐标用 `ScreenToUi` 后的设计坐标；悬停发光限按钮尺寸（h<=80 且 w>=40）。
- **循环动效要确定性 + 可裁剪**：`elapsed % 周期` 定相位（非随机）+ `nvgIntersectScissor` 裁进宿主圆角内。
