- [observed] 会提供游戏截图或飞机参考图，并要求从参考中的低像素轮廓采样出独立网格，而不是沿用旧主题轮廓或只换色；会点名 8bit 太空飞机大战，要求剪影可辨、同波成阵而不是随机散点（出现次数: 2） [scope:gamedev]
- [observed] 要求载具转向有可见过渡动画、视觉模型外轮廓不得超出权威碰撞判定范围，并会直接指出拖拽操作点、模型投影中心、预测轨迹折返点与体素拓扑的错位；偏好以受控游戏态截图验证（出现次数: 3） [scope:gamedev]
- [observed] 偏好 dark-tech 深黑蓝层级与品牌青强调，但会直接否决“完全不是给正常玩家看的”技术黑话 UI；文案必须中文可读，装饰不能压过信息；对外游戏名定为「击碎，飞机大战」（出现次数: 7） [scope:gamedev]
- [observed] 要求敌方按飞机主题重制，保留隐藏砖块血量机制，并让游戏前期敌人保持 1 HP（出现次数: 1） [scope:gamedev]

- [observed] 要求 3D 破坏反馈必须以真实运行态截图验收；当资源路径或自动探针导致画面异常时，先隔离验证并清理正式入口测试注入，再继续交付。（出现次数: 1） [scope:gamedev]
- [observed] 对“UI 消失 / 游戏卡死 / 输入无响应”零容忍且优先级高于视觉打磨；会连续追问要求真正修复。排查时应优先审查后端 Init 致命依赖、事件订阅链和瞬时节点数量预算，并用长时间真实战斗（而非仅菜单截图）验证。（出现次数: 1） [scope:gamedev]
- [observed] 对规则边界与视觉边界的对应关系敏感：会指出顶部反弹发生在屏幕内半空、不同波次飞机仍可能重叠；要求反弹边移出可见画布、编队从生成到移动全程严格 AABB 分离且左右边视觉与规则一致。（出现次数: 1） [scope:gamedev]
- [observed] 不接受敌方像“一堆木箱”，要求按太空飞机大战重做：不同敌机具备可辨识战机外形与类型染色（座舱/引擎/翼面分区），金属质感但颜色鲜明，碎片保留所属机配色；也会注意升级面板同名重复等细节。（出现次数: 1） [scope:gamedev]
- [observed] 会直接指出刷怪过快、经验曲线不合理，要求密度与升级阈值联动调整、前期有喘息且升级平滑；对反弹边界等参数会明确要求用数学方式落地（如两次取值的平均值）；基础间隔经多轮放慢（9.5→11→14s）仍会被嫌快，验收偏好实机体感。（出现次数: 2） [scope:gamedev]
- [observed] UI 验收以实机截图为准：会直接圈出标题异常折行、字号过小过密、点击命中区与视觉卡片漂移等问题；明确反馈“字体平均都太小是 UI 难看的最大问题”，加大一档后仍说“不够”；标签不要低于 15、正文不要低于 17。并且嫌卡片长描述是“小作文”，要求详情一句话说完、数值交给徽标。同一视觉几何的命中常量必须逐值同步，禁止两套布局。（出现次数: 4） [scope:gamedev]
- [observed] 对操作体感的输入限制和等待空窗零容忍：拖拽瞄准必须能在全屏任意位置起手且手指不能遮挡被操控主体（偏好相对位移虚拟摇杆式输入）。但不要为此自作主张发明新机制（v0.10.15 主动召回→v0.10.17 被整体删除）：应优先最小修正（缩短自然流程、修判定 bug），新交互机制先征求确认；会直接否决"多余"机制。（出现次数: 3） [scope:gamedev]
- [observed] 偏好有持续压力与成长的肉鸽幸存者结构：高基地生命（100）、敌人编队推进且单块越线独立扣血、XP/升级三选一与局内强化，并要求明显削弱过强的加速技能；把"质量/设计度 1:1 超过组合参考"作为交付标准（出现次数: 1） [scope:gamedev]
- [observed] 单机只做广告变现不做内购；进入商业化阶段时会主动要求"按商业化重新设计界面"并指定每页出 10 张候选图（一次性拿大批方案再挑，而非单张迭代）；出设计稿时会直接附上现有实机截图作为风格锚点，要求沿用既有美术语言（dark-tech/青）而不是另起一套风格。（出现次数: 2） [scope:gamedev]
- [observed] 对「规则基准线与视觉表现是否对齐」零容忍：会指出扣血的那条线不可见、以及方块越过它之后才扣血。把"看不见"也当缺陷——逻辑正确但玩家看不到等于没做完；要求视觉基准线与规则判定同源同位置。⚠️ 修正时倾向"两条都要"而非替换：会明确要求原有警示线留在原位置、另外新增一条标注真实判定位置，不要擅自挪走玩家已习惯的元素。（出现次数: 2） [scope:gamedev]
