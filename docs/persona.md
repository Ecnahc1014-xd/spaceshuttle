## 工作特征

- 决策风格: [observed] 倾向先消除架构耦合，再进入大规模 3D 开发（出现次数: 1）
- 代码偏好: [observed] 重视渲染与逻辑职责边界和可替换性（出现次数: 2）
- 反馈偏好: [observed] 会直接指出玩法辨识度或技能手感不足，并提供明确目标数值与触发要求（出现次数: 2）
- 工作习惯: [observed] 希望将 2D 玩法表现逐步升级为 3D 体素/载具表现，同时保留既有规则与技能契约；引擎体素物理解锁后倾向先接到现有分层上、探测失败必须回退，而不是推倒规则层；Preview 上会直接指出体素路径的可见性/碎块比例问题（出现次数: 4）
- 性能关注: [observed] 会优先指出严重卡顿、节点泄漏和渲染批次问题，要求先解决性能再继续视觉迭代（出现次数: 1）
- 载具表现偏好: [observed] 运输车辆必须是可拖拽、可飞行、可碰撞的实际发射主体，不能只是底部装饰发射台（出现次数: 2）
- 审美倾向: [observed] 明确偏好正交投影但要求足够斜俯视以表现厚度；载具必须是大运式平头高顶、长货厢、三轴六轮重卡，并通过更浅的独立侧围区分侧面；不接受跑车/皮卡轮廓、方块瓦片车辆、缺色或静态空背景（出现次数: 4）
- 完整度要求: [observed] 不接受只有文字占位或“有功能但无空间反馈”的半成品；四弹药槽要具备完整状态信息，敌船撞线要有相机、材质、冲击波和警示反馈；敌机必须由真实独立方块构成，破坏后对应方块可见缺失，不能用完整模型掩盖规则砖块状态；战斗底部中央要能看见下一波敌人小图（出现次数: 3）
- 参考图使用偏好: [observed] 倾向直接提供游戏截图/飞机参考图，要求从参考中的低像素飞机轮廓采样出网格，而不是沿用旧主题轮廓或仅做风格换色；会点名 8bit 太空飞机大战，要求剪影可辨、同波成阵而不是随机散点（出现次数: 2）
- 运动与判定一致性: [observed] 要求载具转向具备可见过渡动画，并要求视觉模型外轮廓不得超出权威碰撞判定范围；也会直接指出拖拽操作位置、车辆模型投影中心与权威弹珠位置、预测轨迹折返点和体素拓扑之间的错位，偏好通过受控游戏态截图而非只看公式验证（出现次数: 3）
- UI 审美与验收标准: [observed] 不接受只有功能和技术文字的粗糙 UI；会直接根据实机截图要求结构级重构。dark-tech 骨架可留，但文案必须给正常玩家看：中文优先，禁止驾驶舱英文黑话。游戏对外名定为「击碎，飞机大战」，不要用旧名「太空飞机弹珠」。要求信息层级、主视觉、卡片可见性、触摸命中和战斗态 3D 可见性同时成立（出现次数: 9）
- 稳定性红线: [observed] 对“UI 消失 / 游戏卡死 / 输入无响应”零容忍，优先级高于视觉打磨；初始化链中任何可选资源缺失都不应导致整个后端启动失败，瞬时飞散对象必须有同屏数量预算；验收要求覆盖长时间真实战斗而非仅菜单截图（出现次数: 1）
- 边界与编队空间语义: [observed] 对“规则边界 ≠ 视觉边界”敏感：要求顶部反弹边在屏幕可见区之外（载具飞出画面才反弹），左右边对齐视觉；并会发现不同波次飞机仍可能重叠，要求生成与移动全程按完整 AABB 严格分离、不能只检查当批次；对“扣血的那条线”尤其敏感——会指出线不可见、以及方块越过它之后才掉血（视觉基准线必须与规则判定同源同位置）（出现次数: 2）
- UI 打磨偏好: [observed] 在功能跑通后会要求 UI 大修：卡片要有完整可读的详情描述（不是短标签）、自动换行、稀有度/层数/风险等层级信息；倾向去除外部图片依赖改程序化绘制，布局更舒适、信息密度适中；会用实机截图直接圈出标题异常折行、字号过小、点击区与视觉不符等细节问题。明确反馈“字体平均都太小是 UI 难看的最大问题”，第一次加大后仍说“不够”；标签不要低于 15、正文不要低于 17、标题不要低于 28；且嫌卡片长描述是“小作文”，要求详情一句话说完、数字交给徽标；验收以截图可读为准（出现次数: 5）
- 防线结算语义: [observed] 对越线扣血有明确规则要求：按“每行方块”独立碎裂并各自结算 0.5 血向上取整，升级加成只作用在整体合计后的数字而非逐块乘，要求碎裂反馈与权威扣血严格一致（出现次数: 1）
- 变现路径: [observed] 早期「单机只做广告」→ 现明确接受「单机间接联机」架构以解锁内购：钻石由服务端 serverCloud 权威记账、激励视频与真实支付并存；但坚持**不使用平台默认联机大厅的任何形式**（自建入口），大厅问题会精确到时刻（"倒计时到 3 之后变灰"）。会主动要求"按商业化重新设计界面"，并指定每页出 10 张候选图（倾向一次性拿到大批方案再挑）；出图时会直接给出现有实机截图作为风格锚点，要求沿用既有美术语言而不是另起一套；设计稿不止交付图片——要求把界面、机制、图标、交互、存档、支付链路全部落进代码（"做不完不许停"）（出现次数: 4）
- 广告体验红线: [observed] 商业化功能堆满 ≠ 做对了——v0.12.4 升级面板堆了 5 种广告触点被用真机截图痛斥"多到了玩家会骂娘的地步""看三十秒广告延长选卡时间是何意味"，要求整体删除；对"营销内容占常驻大面板行"（付费档案轨）与"平台默认白底弹窗未换皮"同样一票否决，明确"最多来个顶端通知弹窗就行"。⚠️ 新增广告位前先数单局触点总量（≤3-5），营销提示一律轻量顶部条、可关闭、不占版面（出现次数: 1）
- 移动端体验基线: [observed] 在真机上验收并要求：广告播放时游戏必须暂停（"广告期间疑似不暂停"）、任何 PC 快捷键操作（按 P 暂停）必须有触屏等价物（HUD 可见按钮）、模态页必须有完整出口（"游戏结束还不让回主菜单"）。附带要求持续做"用户体验优化、界面优化、图标丰富"——图标风格必须与既有 32×32 dark-tech 像素语言同源（出现次数: 1）
- 主视觉与变现架构观: [observed] 要求把游戏名本身做成**像素超大打字 logo**（程序化、贴合 zpix 语言）而不是普通文字标题；"主页需要重新设计"指反感窗口壳+填充块堆叠；变现入口不止要存在，更要**彼此有逻辑关系**（"所有变现点之间没有良好的整合"）——接受被询问后拍板「闭环三段式」分组（今日福利=免费领取 / 养成收藏=消耗付费 / 钱包=零件→钻石→充值连接器），三色边框语义直接落卡片描边。大结构改造前接受 AskUser 定方向再动手（出现次数: 1）
- 节奏与数值手感: [observed] 会直接指出“刷怪过快、经验曲线不合理”，要求刷怪间隔/同屏密度与升级阈值一起调，偏好前几分钟有喘息、升级平滑而非连升；调整边界这类参数时要求用明确的数学方式（如两次取值的平均值）落地；对刷怪位置与进场动效敏感，要求新敌人整机从屏外平滑进入、不能在屏内凭空出现或突然横向回撤；多次放慢仍会被嫌快（9.5→11→14→18s 基础间隔），同时会抱怨首波入场太慢，间隔与下落速度必须分开调；验收偏好实机体感而非公式（出现次数: 3）
- 3D 箱体验收标准: [observed] 不接受只挂纹理名或只有薄体素的假箱体；要求敌方块有明显厚度、纹理、斜视可见侧面，命中后必须从主体前侧脱离并多轴旋转、飞散、缩放淡出；会直接指出“部分情况下碰撞/碎裂特效丢失”和“物块刷新不及时”，且只要飞机还有存活块，挖空的格子就会变成幽灵块不刷新；要求修复体素后给出明确修理日志，能区分物理步、渲染时序与占用同步问题；验收以运行态截图为准，不能只凭 build 或事件链存在宣布完成（出现次数: 7）
- 交互与表现取舍: [observed] 明确不要预瞄线和弹珠尾迹，优先车辆体量、敌方方块材质、命中后取消碰撞并旋转飞散、飞机之间不重叠；同时要求 UI 不消失且蓝紫主题统一（出现次数: 1）
- 操作手感: [observed] 对输入限制和等待空窗敏感：不接受只能在底部小区域起手拖拽（偏好全屏任意位置起手、手指不遮挡主体的相对拖拽）。重要教训（v0.10.15→17 召回反复）：不要在用户只反馈“空窗/不好用”时自作主张发明新机制（主动召回、预约发射等）——球本来就会自然回落补弹，新增召回被判定“多余”且引出误触吞输出、射不出去等连环问题，两版后被整体回滚；应优先做最小修正（回收点提前、修回收判定 bug、加快自然回落），提出新机制前先和用户确认。新操作要有视觉反馈确认（出现次数: 3）
- 验收方式: [observed] 会在真机/预览实机操作后直接反馈“射不出去”“UI问题明显”“那条线是不可见的”，要求同时定位规则 bug 与渲染表现；修复后以探针+截图双重验证。⚠️ 会明确指出“不可见”也是缺陷——纯逻辑正确但玩家看不到的元素同样算没做完（出现次数: 2）
- 新手引导偏好: [observed] 会主动要求为“初次进入、还没做任何操作”的玩家加引导，且倾向**用图形化手势动画**（如手从上往下拉）而不是纯文字；会指定循环播放、以及动画要表达的具体操作含义（拖拽发射）（出现次数: 1）

## 观察笔记

- [observed] 用户在正式 3D 开发前主动要求分离渲染和逻辑，说明对长期可维护性有明确要求；体素物理新功能也按“探测接入 + 规则零侵入 + 失败回退”落地（出现次数: 2）。
- [observed] 用户认为只改变基础参数不算有特点，更偏好拥有独立触发条件与战术用途的技能（出现次数: 1）。
- [observed] 用户偏好有持续压力与成长的肉鸽幸存者结构：要求基地生命高（100）、敌人编队推进且单块越线独立扣血、XP/升级三选一与局内强化，并要求明确削弱过强的加速技能；把"质量/设计度 1:1 超过组合参考"作为交付标准（出现次数: 1）。
