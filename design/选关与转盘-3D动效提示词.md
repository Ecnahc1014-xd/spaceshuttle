## 0. 通用技术底座（两个界面共用）

### 0.1 已验证可用的渲染管线（必须复用，不要另造）

| 能力 | 实现 |
|---|---|
| 独立 3D 场景 | `Scene()` + `Octree` + `Zone` + `Camera`（局部场景，不进战斗世界） |
| 出图到 UI | `Texture2D:SetSize(w,h,Graphics:GetRGBAFormat(),TEXTURE_RENDERTARGET)` → `RenderSurface` → `nvgCreateVideo` + `nvgImagePattern` |
| 刷新时机 | **只能在 Update 阶段** `surface:QueueUpdate()`，32ms 节流 |
| 参考实现 | `scripts/ui/SupplyPodShowcase.lua`（结算页）、`scripts/ui/VehicleShowcase.lua`（商店展台） |
| 几何 | `CustomGeometry`（`SetNumGeometries` + `BeginGeometry` + `DefineVertex` → **`Commit()`** → 再统一 `SetMaterial`） |
| 材质 | `Material` + `Technique`（`Techniques/PBR/PBRNoTexture.xml` / `PBRNoTextureAlpha.xml`），参数 `MatDiffColor` / `Metallic` / `Roughness` / `MatEmissiveColor` |

### 0.2 必踩的坑（血泪清单，实现时逐条对照）

1. **RT 全黑**：`Viewport` 必须 `SetRenderPath(Forward.xml)`，并把 RenderPath 里每个 `CMD_CLEAR` 改成 `useFogColor=false`、`clearColor=(0,0,0,0)`。只设 SetViewport + SetUpdateMode 不够。
2. **Zone**：`ambientSource = AMBIENT_COLOR`，关闭 bloom/ssgi/ssr/tonemap/autoExposure/fxaa，`tonemapMode = TONEMAP_MODE_NONE`，`fogDensity = 0`。
3. **无 IBL 就别开高金属度**：只有平行光时 `Metallic > 0.6` 会发黑。金属度控制在 0.15~0.35。若要用真金属，给 Zone 挂 `uuid://E4ehad-5axjv7Ml9zasxNx06` 预制天空 IBL（商店展台那套）。
4. **相机宽高比 = RT 宽高比**，否则画面被压扁（结算页第一版就栽在这）。
5. **几何里 `Vector3` 不能用数字下标**（`v[1]=x` 会报 `attempt to index a vector3 value`），只用 `.x/.y/.z`。
6. **`CustomGeometry:Clear()` 会清材质槽**，材质必须在所有 `BeginGeometry` 之后再设。
7. **`Game.DebugForceStageWin()` 之类的验收钩子用完要删**，不要留在正式代码里。
8. 200 个顶层 local 上限：`Scene3DBackend.lua` 已满（AB-166），新状态挂 `uiFx.xxx` 表字段。
9. 本地预览已知噪声（不是代码问题）：`Could not initialize audio output`、缺 `Cube/Day/DaySpecularHDR.dds`、`themis_x64.dll`。

### 0.3 原提示词 → 引擎化替换表（**这是本次的核心**）

| 原提示词要求 | Maker/UrhoX 不支持的现实 | 本项目的替代方案 |
|---|---|---|
| `MeshToonMaterial` + 3~4 阶渐变贴图 | 引擎无 MeshToonMaterial | **方案 A（首选）**：低金属度 PBR + `MatEmissiveColor` 做"亮部自发光"，靠三灯方向读出 2~3 档明暗；**方案 B（可选）**：`engine-docs/recipes/surface-shader.md` 的 SurfaceShader 自写 `light()` 做真分阶（成本高，仅主角模型值得） |
| 法线图 + 深度图后处理描边 | 引擎无 MRT 后处理管线 | **方案 A（全项目统一，首选）**：轮廓壳 —— 几何整体放大 1.03~1.05、翻转绕序、纯黑 `MatEmissiveColor≈0.01` 材质作为最后一段 section，背面剔除后只剩远侧壳 → 外缘一圈均匀黑边（`SupplyPodGeometry` 第 8 段、`VehicleGeometry` 第 7 段即此做法）。**方案 B（可选）**：SurfaceShader 里按 fresnel 或 `1-|N·V|` 在材质内部压暗边缘，得到"零件交界线"，粗细近似固定 |
| 外轮廓粗 / 零件交界细，粗细全程一致 | 无屏幕空间线宽控制 | 轮廓壳的粗细由**放大率**决定，按展示尺寸反算：`放大率 = 1 + 目标像素宽 / 屏幕像素高 × 2`。零件交界靠**几何留缝**（真缝隙 + 暗色凹槽条）自己读出来，不画线 |
| 1.5x 超采样 + MSAA | `graphics:SetMode()` 已禁用，无法开 MSAA | **RT 尺寸 ×2 超采样**：`ResolveSize` 按展示区物理像素 ×2 申请 RT（上限 1280×1280），`FILTER_BILINEAR` 让 NanoVG 缩回显示尺寸 → 边缘自然抗锯齿。实测 3.2M 像素内移动端可接受 |
| 标题用 Titan One / Lilita One | 无 web 字体 | 用引擎像素字 `DrawPixelText`（zpix）+ **逐字缩放/位移动画**：每字独立 `scale` 从 2.6 → 0.86 → 1.10 → 1.0，`y` 从 -60 落到 0，逐字延迟 80ms，再叠一层偏移 4px 的深色描边字 + 8px 投影 |
| 粒子 / 光柱 / 光晕 | 无粒子系统（本项目已明确不用粒子） | 几何化：光柱 = 圆锥/圆柱 + `PBRNoTextureAlpha`（低 alpha + emissive + 加法混合）；光晕 = 同心环带（`RingBand` 生成器）；星点 = 小八面体/菱形群 + 自转 |
| 圆润厚重造型 | 无 RoundedBoxGeometry | 自写**倒角盒**生成器（6 面 + 12 条 45° 倒角带 + 8 个角三角，见 `SupplyPodGeometry.ChamferBox`），倒角 0.03~0.09 |
| 宝石切面 | 无图片级法线贴图 | 低多边形实体：钻石用"双锥 + 台面"（`Diamond`），宝石用八面体，靠面片法线差读出切面 |
| 脚下随高度变化的柔和投影 | 无阴影贴图 | ① Zone 不投真阴影；② 用一块**扁平暗色圆盘**（`RingBand` 半径 1.7）贴地随高度缩放/淡化；③ 或半透明 alpha 材质的椭圆面片 |
| 逐帧后处理 bloom | 引擎有 bloomPlus 但已关 | 用 CSS 式叠加不存在，改为**几何发光层 + 加法混合**，必要时给 Zone 单独开 `bloomPlusEnabled`（仅展示场景，实测可开） |

### 0.4 性能预算（硬指标）

- RT 像素 ≤ 3.2M（例如 900×640 ×2 超采样封顶）
- 单场景静态顶点 ≤ 30k（结算页当前 30k 左右含轮廓壳，供参考）
- 稳态：**每帧 0 顶点上传**，只改节点 `position/rotation/scale` 与材质颜色/自发光
- draw call ≤ 8（每个 CustomGeometry section 一个）
- UI 侧：3D 只负责"图的矩形"，所有文字/按钮仍走 NanoVG（命中检测与绘制共用同一套布局函数）
- 移动端降级：几何段数腰斩、RT 超采样 ×1.5、关闭轮廓壳（改 SurfaceShader 边缘）

### 0.5 通用动效语言（两个界面都必须有）

- **入场**：3D 从 0.86 缩放 + 下移 30px 弹到 1.0，250ms，`easeOutBack`；UI 文字随后逐字砸入。
- **待机**：主体绕竖轴 ±12~20° 缓慢摆动（周期 6~9s），同时上下浮动 ±0.05，投影随高度缩放/淡化。
- **活动部件**：必须真实运动（开合、转动、指针摇摆），不能是贴图位移。
- **等级色**：至少 4 档（银/蓝/紫/金 或 绿/蓝/紫/金），换色时同步切换 主体高光色 / 轮廓光色 / 背景热区 / 标题色 / 光效色。
- **收尾**：动画结束停在"可读状态"（不要停在半路），并允许点击跳过。

## 1. 选关界面（Stage Select）提示词

### 1.1 界面角色

竖向列表 + 关卡缩略展示。当前是 2D 卡片列表（`scripts/ui/StageSelect.lua`）。
目标：把"当前选中的关卡"变成一块 **3D 关卡徽章展台**，列表保留 2D 滚动，选中的关卡在顶部有 3D 演出。

### 1.2 主体（真 3D）

**「第 N 关」纪念徽章 + 底部基座**，全部实体建模：

- **徽章盘**：倒角圆柱（半径 0.55、厚 0.16、倒角 0.03），正面凸起一圈矮边框（环带）
- **关卡数字**：用**实体几何**挤出 1~3 个数字（用 7 段数码管式的方块拼数字，或简化成"三根横杠 + 竖杠"的体块），字面离盘面 0.04，带 0.02 倒角 —— 不用贴图
- **等级星章**：三颗小星（挤出 + 倒角），随星级点亮，未点亮为暗灰实体
- **基座**：八边形台座（倒角盒旋转 22.5°），顶部一圈发光槽（等级色 `MatEmissiveColor`）
- **侧翼**：两片薄装甲板（左右各一），纪念徽章展开时向外翻开 20°，静态展示时为收起角度
- **专属标识**：按关卡分组换色（第 1~10 关 银、11~20 蓝、21~30 紫、31+ 金），并在地形底座上放一个"该关敌人主类型"的低多边形剪影（小飞机/坦克方块，3~5 个方块组合即可）

### 1.3 相

- 透视、fov 32~36，略俯视，相机距离让徽章占展示区高度 70%
- 三灯：冷白主光（左上）、天光 Hemisphere、**等级色轮廓光**（右后逆光）
- 徽章**绕竖轴 ±16° 摆动**，周期 7s；上下浮动 ±0.05

### 1.4 动效时序（选中关卡时播放，1.8s）

| 时间 | 事件 |
|---|---|
| 0.00–0.25 | 徽章从 0.86 缩放 + 下移弹入（easeOutBack） |
| 0.10–0.45 | 侧翼装甲板向外翻开 20° |
| 0.30–0.60 | 基座发光槽点亮（emissive 0→满） |
| 0.40–0.90 | 星章逐颗弹出（0.15s 间隔，超调 1.2 后落定） |
| 0.55–1.00 | 关卡数字**从下往上浮入**（数字体块 `y` 从 -0.3 到 0，带 0.06 过冲） |
| 0.60–1.10 | 标题「第 N 关」逐字砸入（NanoVG） |
| 1.10–1.80 | 一轮环绕光扫过（环带 emissive 相位），回落到待机摆动 |

切换关卡时：旧徽章向左下淡出（150ms），新徽章重播全套。

### 1.5 与现有 UI 的接缝

- 3D 只占"顶部展示区"（约 `520×300` 设计像素），列表仍在下方 2D 滚动
- 列表选中项变化 → 触发上面的 1.8s 演出（节流：连续滑动时只在停留 200ms 后播放）
- 点「开始战斗」时：3D 徽章放大并闪白 120ms 作为转场起点（与既有 `StageIntro` 衔接）

### 1.6 验收

1. 换关能明显看出"徽章换了、颜色换了、星数换了"
2. 侧翼翻开的动作真实（不是缩放假动）
3. 数字是凸起实体，斜看有厚度与投影
4. 待机摆动时看得到徽章侧厚与基座
5. RT 超采样下外轮廓干净，无锯齿（尤其数字边缘）

## 2. 幸运转盘界面（Lucky Wheel）提示词

### 2.1 界面角色

现有转盘（`scripts/ui/` 内相关屏）是 NanoVG 2D 扇形。
目标：换成**实体 3D 转盘**，旋转有真实加减速，中奖有飞出奖励的演出。

### 2.2 主体（真 3D）

- **转盘盘体**：厚度 0.18 的圆盘（倒角 0.02），分 8 个扇区：用**实体隔条**（薄梯形棱，沿半径方向，8 条）隔开，扇区面按等级色分 4 档（银/蓝/紫/金，每两格一档）
- **扇区标识**：每个扇区放一个**实体小图标**（零件=齿轮简化成"圆柱 + 6 齿"、钻石=双锥、星章=挤出五角星、广告券=小方牌），离盘面 0.05
- **中心宝石**：低多边形八面体（半径 0.22），持续自转，等级色 emissive
- **指针**：顶部悬挂的实体三角锥（指向前下方），**有轻微弹簧摆动**（命中时被"顶"一下再回弹）
- **外圈**：环带 + 12 颗实体灯珠（小球，逐个点亮走马灯）
- **基座**：倒角盒 + 四个斜切角块

### 2.3 相机与灯

- 透视，fov 34，正面略俯（能看全盘面），相机绕竖轴做极缓慢 ±3° 呼吸
- 三灯同结算页：主光 / 天光 / 等级色轮廓光
- 待机：整盘每 5s 自转 15°（"不甘心"的轻微转动），中心宝石常转

### 2.4 旋转与结果演出（一次抽奖总时长 4.2s）

| 时间 | 事件 |
|---|---|
| 0.00–0.20 | 指针被"压"下去 0.05（预压） |
| 0.20–0.35 | 突发放开，盘体进入高速旋转（8 rad/s） |
| 0.35–2.10 | 匀减速：`ω(t) = ω0 * (1-t/T)^2.2`，总角度 ≈ 5.5 圈 + 目标扇区对齐 |
| 2.10–2.45 | 指针依次"咔"过 4~6 个隔条（每格一次 0.06 的摆幅，逐次衰减） |
| 2.45–2.75 | 停在目标扇区：该扇区面 emissive 脉冲 3 次，灯珠走马灯加速 |
| 2.75–3.40 | 奖励物件**从盘面中心飞起**（y 0→1.1，带 0.1 过冲），放大到 1.4 倍并自转，其余元素压暗 |
| 3.00–3.60 | 奖励名称逐字砸入（NanoVG），等级色光柱从中心升起 |
| 3.60–4.20 | 光柱收束，奖励物件落回中心并缩小消失，转盘回到待机 |

- 抽奖时**禁用输入**，且允许点击"跳过"直接到 3.40 的定格状态
- 网络请求在 0.00 发起，若 2.10 前未返回，则盘体在 2.10 处**悬停减速**等待（不硬停），返回后再减速到目标格

### 2.5 验收

1. 减速曲线有"越转越慢"的手感，不是线性
2. 指针逐格"咔哒"过隔条（视觉 + 摆幅）
3. 中奖物件是实体 3D，飞起时有厚度与投影
4. 四个等级的格面颜色区分明显（一眼看出稀有度）
5. 连续抽奖不累积内存（RT 只建一次，几何只建一次）

## 3. 两个界面共用的验收清单

- [ ] 3D 在 30fps 节流下仍有"流畅感"（旋转相位按真时间推进，不按帧数）
- [ ] 断网/资源缺失时不崩：3D 不可用则回落到现有 2D 界面，**不留空白块**
- [ ] 移动端 1080×1920 与桌面宽屏都验证过比例（相机宽高比跟随 RT）
- [ ] 首次进入有 <300ms 的建场景耗时，不能卡主线程（可懒加载 + 首帧占位）
- [ ] 所有动画可在 `GetDiagnostics()` 里查到状态（openProgress / spinAngle / phase / vertices / rebuilds）
- [ ] 描边粗细在 720p 与 1080p 下视觉一致（按展示尺寸反算放大率）

## 4. 落地顺序建议

1. **先做选关**（结构简单、复用结算页管线最多，风险低）
2. 转盘需要"结果驱动旋转"的状态机，复杂度高一档，放在后面
3. 每做一个，先只做"几何 + 待机 + RT 出图"，截图确认清晰度，再加动效
4. 每个界面都保留 2D 降级路径，避免 3D 失败导致界面不可用
